# Presidential Simulator

Браузерная политико-экономическая стратегия. Игрок получает случайную страну и президента, формирует правительство, ведёт кампанию, принимает законы и указы, управляет экономикой и ведёт переговоры с другими государствами.

## Архитектура

- `frontend/` — статический интерфейс GitHub Pages.
- **Neon PostgreSQL `presidential-simulator`** — игровые аккаунты, сессии, сохранения, страны, указы, дипломатия, министры, армия и события.
- **Neon Function `nettleapi`** в проекте Nettle Group — существующий API авторизации и обычных игровых операций. Использует текущего Telegram-бота `@Verify_NettleBOT`.
- **Neon Function `presidaidev`** в отдельной ветке проекта Nettle Group — дополнительный API для ИИ-операций. Она подключается к той же основной игровой базе через ограниченную роль `presidentapi`. Функции `nettleapi` и авторизация не заменяются.
- **OpenRouter** — модельный API, вызываемый только серверной функцией. Ключ не попадает в браузер.

Cloudflare, Vercel и отдельный сервер для сайта не используются. Так как игровая база находится в регионе без поддержки Neon Functions, серверные функции размещены в уже существующем проекте Nettle Group.

## Вход через Telegram

1. На сайте нажать «Войти через Telegram».
2. Сайт откроет `www.nettlegroup.space/presidential-login.html`.
3. Авторизоваться через существующий `@Verify_NettleBOT`.
4. Сервер Nettle проверит HMAC-подпись Telegram, создаст одноразовый код на 3 минуты и вернёт игрока в игру.
5. Игра обменяет код на случайный серверный токен. В БД сохраняется только SHA-256-хэш токена; срок игровой сессии — 7 дней.

## API и секреты

Основной API `nettleapi` продолжает обслуживать авторизацию и стандартные игровые маршруты. Дополнительный AI API имеет отдельный публичный адрес:

`https://br-nameless-term-b9ex7292-presidaidev.compute.c-7.eu-central-1.aws.neon.tech`

В `frontend/config.js` публично указываются только адреса API и страницы входа. В секретах Neon Function находятся:

- `PRESIDENTIAL_DATABASE_URL` — строка подключения ограниченной роли `presidentapi` к основной игровой базе.
- `PRESIDENTIAL_GAME_ORIGIN=https://merekwi.github.io`.
- `OPENROUTER_API_KEY`.
- Необязательный `OPENROUTER_MODEL` — модель OpenRouter; по умолчанию используется `openai/gpt-4o-mini`.

Существующие `TELEGRAM_BOT_TOKEN`, `SESSION_SECRET`, `SITE_ORIGIN` и `INITIAL_ADMIN_TELEGRAM_ID` в `nettleapi` сохраняются. Не добавляйте bot token, database URL или OpenRouter key в `frontend/` и не коммитьте секреты в GitHub.

## Военная стратегия

Военная система обслуживается основным игровым API `nettleapi` и хранит состояние в той же базе кампании.

- **Комплектование:** численность строится из боеспособного населения, обученного резерва и действующих контрактов. Число желающих служить зависит от зарплатного индекса, общественной поддержки и рынка труда. Законы о добровольной службе, выборочном и всеобщем призыве задают юридические пределы.
- **Государственные программы:** модернизация вооружённых сил, подготовка резерва и развитие контрактной службы финансируются из казны и исполняются помесячно.
- **Технологии:** девять направлений военных исследований имеют уровни 0–5; очки исследований накапливаются по месячному оборонному бюджету.
- **Патрули:** президент прокладывает маршруты на карте, выбирает подразделение и тип патруля. Точки сохраняются как координаты и отображаются на стратегической карте.
- **Войны:** начало конфликта — отдельное политическое решение. По умолчанию активной войной управляет автономный штаб ИИ, который проводит операции независимо от открытой игры. Президент задаёт директиву и при необходимости переключается на ручное управление.
- **Ручное управление:** карта поддерживает масштабирование колесом мыши и кнопками, перемещение перетаскиванием, постановку приказов на продвижение, оборону, удержание, разведку, отход и поддержку подразделений.
- **Отдельная вкладка «Военная карта»:** оперативная карта рисуется собственным SVG-рендерером непосредственно в браузере из геометрии государств, хранящейся в `frontend/assets/world-countries.geojson`. Для военной карты не используются Leaflet, внешние картографические библиотеки, спутниковые тайлы или картографические CDN. Масштабирование, перемещение, патрульные маршруты и постановка приказов работают внутри собственного SVG-интерфейса. Верхняя геополитическая карта остаётся отдельной и не затрагивается.

Военные маршруты API:
- `POST /api/presidential/game/military` — законы, контракты, бюджет, исследования, резерв, программы, патрули, начало войны, директивы, боевые приказы, оперативный ход и прекращение огня.
- `GET /api/presidential/game/current` — текущее состояние армии, технологии, войны и патрули вместе с остальным сохранением.

Миграции находятся в `database/migrations/`: `003-military-systems.sql` — военная система, `004-continuous-calendar-clock.sql` — календарь и скорость симуляции. Логика военной модели и тесты находятся в `neon-function/war-engine.cjs` и `neon-function/war-engine.test.cjs` репозитория `Merekwi/nettlegroup`.

## Непрерывный игровой календарь

Пошаговое завершение месяца убрано. В кампании отображаются текущая дата и время, а игрок выбирает скорость симуляции: **x1, x2, x4, x6, x12 или x16**. При x1 проходит одна игровая минута за реальную секунду; остальные скорости пропорциональны этому значению. Интерфейс обновляет часы каждую секунду, а сервер синхронизирует и сохраняет календарь каждую минуту.

Экономика, госпрограммы, набор контрактников, военные исследования и другие месячные процессы пересчитываются автоматически при наступлении нового месяца. Внутренний старый счётчик сохранения оставлен только для совместимости с уже существующими данными — он не является игровой кнопкой или системой ходов. Очки действий больше не ограничивают решения президента. Сроки общественных обсуждений, референдумов и дипломатических ответов рассчитываются по календарным датам.

- `POST /api/presidential/game/clock` — применить скорость времени и синхронизировать дату.
- `GET /api/presidential/game/current` — получить сохранённую дату, время и текущую скорость.
- Старый маршрут `POST /api/presidential/game/advance` отключён.

Серверное расписание Neon `presidential-calendar-clock-every-minute` запускает календарь каждую минуту. Оно работает независимо от открытой вкладки браузера.

## ИИ-механики

- **Указы:** игрок пишет инициативу свободным текстом. ИИ формирует проект официального указа, анализирует бюджет, выполнимость и риски. Публикация — отдельное действие игрока.
- **Последствия указов:** сервер принимает только разрешённые числовые изменения, ограничивает их диапазоны и применяет в транзакции. ИИ не выполняет SQL и не может напрямую менять сохранение.
- **Выборы:** игрок формулирует собственные предложения к вопросам программы. ИИ оценивает реализуемость и реакцию шести групп избирателей; решения и поддержка сохраняются в кампании.
- **Политические действия:** свободный текст — выступления, работа с гражданами, коалиции, патронаж, коррупция, захват институтов и попытка переворота. Исход переворота определяет серверная вероятность на основе состояния страны.
- **Дипломатия:** свободный диалог с руководителями других государств. В контекст входят интересы стран, отношения, договоры и история переписки. Ответ и изменение отношений сохраняются.

AI-маршруты:

- `POST /api/presidential/ai/decree/draft`
- `POST /api/presidential/ai/decree/publish`
- `POST /api/presidential/ai/election/decision`
- `POST /api/presidential/ai/election/action`
- `GET /api/presidential/ai/diplomacy/history?relationId=...`
- `POST /api/presidential/ai/diplomacy/message`
- `GET /api/presidential/ai/health` — техническая проверка базы и наличия AI-ключа, без выдачи секретов.

Все изменяющие состояние маршруты требуют существующую авторизованную игровую сессию. Перед записью сервер блокирует активное сохранение, перепроверяет его актуальность, валидирует ответ ИИ и фиксирует изменения, событие и аудит в одной транзакции.

## Тестирование и развёртывание

Ветка `feature/ai-political-engine` содержит отдельный backend, проверки синтаксиса, детерминированные тесты и workflow для развёртывания AI API. Тесты запускаются на Node.js 24 через `npm test` в `backend/presidentai`.

Развёртывание дополнительной функции не удаляет и не заменяет `nettleapi`. Подключение к игровой базе выполняется через ограниченную роль `presidentapi`; игровые сохранения и таблицы авторизации остаются в существующей базе.
